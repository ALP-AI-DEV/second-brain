# Operation: in-depth setup

Synonyms: let's set up the base in depth, grill me, interview me, in-depth setup.

Onboarding gives the minimum to get started. Here the agent works out in rounds how the user works, so
that sections, synonyms, templates and "External" rules fit them. The operation is voluntary: offer it,
don't push it. It usually takes 10–20 minutes.

**Reminder.** If "Who I am" → "In-depth setup" says `postponed`, offer it once more when `wiki/` has 15+
pages or a week has passed. Then set `postponed, reminded YYYY-MM-DD` and don't remind again.

## How to ask

- **A round** is every question that can be answered right now. A question whose answer depends on
  another question that is still open goes to the next round. More than 7 questions — split the round.
- **Format** — numbered questions, so the user can answer by number ("1 yes, 2 the second option, 3 no,
  because…"):
  ```
  ❓ 1. Keep a folder for each team member?
  ➡️ I suggest yes: the base already has five one-on-ones, and they contain agreements.
  ```
  A decision about the base gets a recommendation with a reason. A question about the person ("what
  matters to you") gets no recommendation — give an example answer instead.
- **Find facts yourself.** Read the section map, `notes/`, entity profiles, the log. Don't ask what the
  base already shows. Ask the user about decisions and about what only they know.
- After a round — 1–2 lines of "here's what I understood", so the user can correct you.
- Asked for one question at a time — ask one at a time.

## What to find out

This isn't a questionnaire: skip what's settled, add what comes up.

1. **Work.** Roles (manager, individual contributor, freelancer…), what the day is made of, what slips
   through most often.
2. **Entities.** Who and what they keep track of over time: clients, projects, team members, courses,
   cases. Roughly how many, and what they call them.
3. **Flow of material.** Where it comes from (meetings, email, messengers, documents), what to always
   process, what goes as one line into a catalog, what not to keep.
4. **Questions to the base.** What they'll ask ("prepare me for the meeting", "what did I promise") and
   how they look things up — by person, company, date, topic.
5. **Privacy.** What must not go outside; whether it holds other people's personal data; personal stuff — in this base
   or separately.
6. **Tools.** What's connected to the agent (email, calendar, tracker, transcriber) — check yourself,
   ask which to use. What to cross-check with as the second model.
7. **Rhythm.** How often to check the base and reflect, whether to remind.

## Wrapping up

It ends when no open decisions that affect the work are left, or the user said "stop".

1. **The outcome in one message:**
   - what to write into "Who I am" — as ready text;
   - the restructure plan — sections, synonyms, templates, "External", moves and link fixes
     (per `operations/restructure.md`);
   - new rules for `AGENTS.md` — as ready text.
2. One question: "Shall I carry it out?" After a "yes" — do all of it; in "Who I am" → "In-depth setup":
   `done YYYY-MM-DD`. Log entry: `## [YYYY-MM-DD] in-depth setup | what changed`.
3. **"Stop" in the middle of the rounds** — show the outcome of what's been answered and ask whether to
   apply it. Leave the unanswered empty; don't apply recommendations without a "yes".

It can be run again — when the work has changed. Then start from what changed, not from scratch.
